<objective>
Wire pdfium, Poppler, and MuPDF as three independent rasterizers, assert their unedited-corpus
renders are pixel-identical to each other, and run `qpdf --check` plus `pdfcpu validate` against
every corpus file — all in CI, all against the whole public corpus.

Purpose: ENG-02 and ENG-03 are the harness itself — Gate G0's central claim that "every correctness
claim this project will ever make has a machine that checks it." On an identity transform (no edits
exist yet in Phase 1), the masked-diff assertion reduces to cross-engine agreement on the unedited
page, which is exactly the proof this phase needs before Phase 2/3 build anything on top of it.

Output: `harness/render_diff.py`, `harness/masked_diff.py`, `harness/run_corpus_harness.py`,
`Dockerfile.ci` with pinned renderer versions, a `harness` CI job.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| CI container ↔ every corpus PDF (including deliberately malformed/encrypted fixtures) | Three separate native renderer binaries plus two structural validators parse untrusted-shaped input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-04-01 | Denial of Service | A malformed/decompression-shaped corpus fixture hangs or exhausts memory in a renderer subprocess | mitigate | Every subprocess call (`pdftoppm`, `mutool draw`, `qpdf --check`, `pdfcpu validate`) wrapped with an explicit `timeout=` argument; a timeout is recorded as a failure for that file, not a hung CI job; CI's own job-level timeout is the backstop |
| T-04-02 | Elevation of Privilege / memory corruption | Native renderer CVEs triggerable by crafted PDFs (pdfium, Poppler, MuPDF all have documented CVE history per research/PITFALLS.md's attack table) | accept | Runs only in an ephemeral GitHub Actions runner with no persistent secrets beyond the private-tier bucket credentials already scoped and isolated in Plan 01-03; full process sandboxing (RLIMIT_AS, seccomp, no-network) is explicitly Phase 4 scope for the public-facing service — accepted here rather than silently deferred, since this is CI/maintainer-only exposure, not a public endpoint |
| T-04-03 | Tampering | Renderer version drift between local dev and CI silently redefines "pixel-identical" over time | mitigate | Exact version pins in `Dockerfile.ci` (Task 1); an unpinned rasterizer upgrade changing antialiasing would otherwise read as a false regression |
| T-04-SC | Tampering (supply chain) | System packages `poppler-utils`, `mupdf-tools`/`mupdf`, `qpdf`, `pdfcpu` binary | accept | All four are named directly by research/ARCHITECTURE.md §10 and research/STACK.md as the recommended CI-only validators/renderers; no PyPI/npm install involved, standard distro/GitHub-release packages |
</threat_model>
