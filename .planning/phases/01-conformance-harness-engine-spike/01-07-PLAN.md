<objective>
Grow the public tier from 17 to at least 100 real, wild-harvested documents, selected for
**producer diversity** rather than count, so Gate G0 clears from public sources alone.

Purpose: Gate G0 requires 100–300 documents and the corpus currently holds 17. More importantly,
10 of those 17 come from just two sources (7 IRS, 3 veraPDF fixtures), and the roadmap's
"weighted toward invoices and contracts" is unmet — the only two invoices are scans from 1842 and
1905. Phase 2's forward-encoding decision table has at least five branches selected by the
`Symbolic` flag, `/Encoding` presence, and which cmap subtables the embedded font carries. Those
branches are exercised by *producer variety*, not by document count: a hundred files from one
generator exercise one code path. Building the interpreter against today's corpus would make it
look correct while leaving the long tail untested — the precise failure this phase exists to
prevent.

This also unblocks CI. `corpus-size-gate` is wired blocking on `main`/`release/*` and currently
red; a permanently-red required check trains everyone to ignore it.

Output: ≥83 additional documents in `corpus/public/`, extended `corpus/manifest.json`,
`corpus/sources.md`, and reproducible harvest tooling.
</objective>

<threat_model>
Scope: this plan downloads untrusted PDF files from public networks onto a developer machine and
into CI, and commits them to a repository. There is no served request path and no user data.

| Threat | Vector | Mitigation |
|---|---|---|
| Tampering | A fetched document is not what the source intended (MITM, mirror compromise) | HTTPS-only fetches; sha256 recorded in the manifest at harvest time, and `corpus/validate_manifest.py` re-verifies every hash on every CI run, so later drift fails loudly |
| Denial of service | A decompression bomb or pathologically nested document is committed and then parsed by every future CI run of the harness | Cap accepted file size at harvest; the harness (01-04) already wraps every render and subprocess call so a hostile file is recorded as a failing row rather than an unhandled crash |
| Spoofing / licence contamination | A document's redistribution terms are not what the source claims, exposing the project to a takedown | Record the licence per source in `corpus/sources.md`; skip any document whose terms cannot be confirmed. Prefer public-domain government output and explicitly-licensed test corpora |
| Information disclosure | A harvested "public" document turns out to contain personal data | Public-source-only by construction; the private tier (D-01) remains the sole home for anything sensitive and is never committed. If a harvested file is found to contain PII, remove it and record the removal |
| Repository integrity | Large binaries bloat git history permanently | git-lfs per the existing `.gitattributes`; size cap enforced at harvest |

Out of scope: hostile input reaching a served endpoint (Phase 4), and any credential handling —
this plan touches only public, unauthenticated sources.
</threat_model>
