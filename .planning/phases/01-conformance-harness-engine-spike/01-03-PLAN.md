<objective>
Build the independent verifier that cross-checks the corpus manifest against the actual files
using only plain structural inspection (D-04), and the private-tier fetch mechanism that treats a
missing bucket credential as a normal state rather than a failure (D-01, D-02).

Purpose: D-04's manifest declarations are worthless without an independent check that a document
actually has the category it claims — and that check must not reuse the future content-stream
interpreter, or it becomes circular. D-02's fork-PR/fresh-clone story only works if absence of the
private tier is silent and green, not a warning or a red build.

Output: `tools/probe_corpus.py`, `tools/fetch_private_corpus.py`, `corpus/private-manifest.json`,
two CI jobs (`corpus-public`, `corpus-private-gate`) in `.github/workflows/corpus.yml`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| CI runner ↔ external private bucket | Authenticated fetch of real invoices/contracts using CI-scoped secrets |
| CI/local prober ↔ corpus files (including deliberately malformed/encrypted fixtures) | Structural inspection of untrusted-shaped PDF bytes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-01 | Information Disclosure | `PRIVATE_CORPUS_TOKEN` / bucket credentials | mitigate | Fetch script never prints credential values, only status/skip/error messages; GitHub Actions automatically redacts values referenced via `${{ secrets.* }}` from logs |
| T-03-02 | Tampering | Private-tier bytes accidentally committed to git history | mitigate | `.gitignore` entry for `corpus/private/` plus this task's explicit `git check-ignore` verification; a permanent leak risk if ever bypassed, flagged here for a future pre-commit scan as a nice-to-have, not blocking this phase |
| T-03-03 | Denial of Service | Prober hangs/crashes on a deliberately malformed corpus file | accept | pikepdf's object-layer access is resilient to malformed content streams since it operates on the xref/object table, not content-stream tokens; residual hang risk accepted at Phase 1's small-corpus, CI-only, maintainer-only exposure scale — full process sandboxing (RLIMIT_AS, seccomp, timeouts) is explicitly Phase 4 scope (INGE/PRIV requirements) for the public-facing service, not this CI tooling |
| T-03-SC | Tampering (supply chain) | No new PyPI/npm packages introduced (stdlib `urllib.request`, `unittest.mock`, `http.server` only) | accept | Ponytail ladder followed — stdlib solves the private-tier fetch without a cloud SDK dependency; no [ASSUMED]/[SUS] package introduced |
</threat_model>
