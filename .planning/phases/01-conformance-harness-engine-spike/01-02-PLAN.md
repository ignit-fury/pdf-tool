<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Local/CI machine ↔ sourced PDF bytes | Handling untrusted-shaped content while sourcing, hashing, and deliberately corrupting/encrypting fixtures for the corpus |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-01 | Denial of Service | sha256 hashing / git-lfs tracking of malformed fixtures | accept | Hashing and lfs tracking operate on raw bytes only, never invoke a PDF parser — negligible hang/crash risk at this stage |
| T-02-02 | Information Disclosure | Public-tier document sourcing | mitigate | Task 1 requires explicit license/source verification before every commit; real private invoices/contracts are never sourced for the PUBLIC tier — that is precisely why D-01 splits a private tier out to an uncommitted bucket |
| T-02-03 | Tampering | Corpus files swapped/corrupted post-commit without detection | mitigate | sha256 recorded in manifest.json (this plan); independently re-verified by the prober in Plan 01-03 (D-04) |
| T-02-SC | Tampering (supply chain) | `ocrmypdf` (system tool, used only to generate one fixture, not a runtime dependency) | accept | Named directly by research/PITFALLS.md as the recommended generation method for the OCR'd-scan category; not installed into the product's runtime dependency tree |
</threat_model>
