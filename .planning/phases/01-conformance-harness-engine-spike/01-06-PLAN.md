Prototype the TJ-array width-fitting algorithm — the one mechanism no PDF library provides — and
prove it hits |Δwidth| < 0.5pt on a hand-picked real text run, preserving the test cases and
measured results for Phase 3 even though the prototype code itself is throwaway.

write from scratch, with kerning-split runs as the documented top failure source. Getting the sign
convention and the priority-ordered delta-absorption strategy right here, cheaply, on one run,
retires the risk before Phase 3 builds the real rewrite engine on top of it.

Output: `spike/tj_refit_prototype.py`, `TJ-REFIT-RESULTS.md`.

  <name>Task 1: Prototype the TJ-refit width-fitting algorithm</name>
  <files>spike/tj_refit_prototype.py, spike/fixtures/tj_refit_sample.pdf, tests/test_tj_refit_prototype.py</files>
  <read_first>
    .planning/research/PITFALLS.md (Pitfall 5, "Naive replacement wrecks advance widths" — the full algorithm, the priority-ordered absorption strategy, and the TJ sign convention)
    .planning/research/ARCHITECTURE.md (§"Width Fitter" component, §6)
    .planning/research/STACK.md (uharfbuzz section — `hb.shape()` returns kerned `x_advance`)
  </read_first>
  <behavior>
    - `fit_run(original_advance_pt, replacement_text, font_path, font_size_pt) -> FitResult` returns
      a result whose `delta_pt` (computed total advance minus `original_advance_pt` after fitting)
      satisfies `abs(delta_pt) < 0.5` for both a replacement shorter than the original text and a
      replacement longer than the original text, when the delta is within the trailing-kern
      absorption range (roughly one space width).
    - The TJ sign convention is implemented correctly: a positive kern adjustment measurably
      tightens (reduces) the computed total advance, never widens it.
    - When the delta exceeds what trailing-kern absorption alone can close, the function raises or
      returns a clearly-flagged `NotImplementedError`/refusal result rather than silently producing
      a wrong number — this prototype does not need the full Tz/refuse ladder, only the first two
      priority steps (trailing TJ kern, then inter-word kern distribution) plus an honest stub for
      the rest.
  </behavior>
  <action>
    Bundle one small, real, hand-picked single-page PDF as `spike/fixtures/tj_refit_sample.pdf`
    (source it the same way Plan 01-02 sources corpus files — a real invoice-like document with
    justified or plain body text — independently of the corpus since this plan runs in Wave 2
    without depending on Plan 01-02). Write `spike/tj_refit_prototype.py` implementing exactly the
    behavior above: (1) read the chosen run's original text-showing operator and total advance
    width from the font's `/Widths` or `/W` array via `fontTools`; (2) shape the replacement string
    with `uharfbuzz`'s `hb.shape()` to get kerned per-glyph `x_advance` values; (3) compute the
    delta between the replacement's total shaped advance and the original run's advance; (4) absorb
    the delta first via the trailing `TJ` kern number — remembering the number is SUBTRACTED from
    the position, so a positive value tightens (moves left) and a negative value widens — then, if
    the delta exceeds roughly one space width, distribute it across inter-word kerns in the run;
    (5) assert the resulting computed advance is within 0.5pt of the original. Write
    `tests/test_tj_refit_prototype.py` with at least two cases: a replacement shorter than the
    original text, and a replacement longer than the original text, both asserting
    `abs(delta_pt) < 0.5`, plus one case asserting the sign-convention behavior directly (a known
    positive kern value measurably reduces computed advance versus a zero kern value).
  </action>
  <acceptance_criteria>
    `pytest tests/test_tj_refit_prototype.py -q` passes all cases; the sign-convention test
    explicitly demonstrates positive-kern-tightens, not widens; running the prototype against the
    bundled sample with both a shorter and a longer replacement produces `|Δwidth| < 0.5pt` in both
    directions.
  </acceptance_criteria>
  <verify>
    <automated>pytest tests/test_tj_refit_prototype.py -q</automated>
  </verify>
  <done>Prototype demonstrates the width-fit algorithm meets the 0.5pt threshold on the hand-picked run in both length-delta directions, with the TJ sign convention proven correct by a dedicated test.</done>
