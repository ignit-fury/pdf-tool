<objective>
Build `engine/recipe.py` -- the module 03-CONTEXT.md's D-09 names as an edit's actual representation
(a JSON list of `{run_id, new_text}` ops) -- and wire a `pdftool edit` subcommand over it. This is
the phase's own composition point: it is where `engine/fit.py` (03-03), `engine/fonts.py` (03-04/
03-05), and `engine/rewrite.py` (03-06) are actually driven together against a real recipe, for the
first time in the phase. `engine/rewrite.py`'s own docstring already names this coupling --
`rewrite_run` takes an ALREADY-BUILT `(SubsetFont, pikepdf.Object)` substitution target as a
parameter specifically so it never builds its own font, and this module is the one place that
builds exactly one per family per document (D-13).

**This plan also closes a real prerequisite gap, not a hypothetical one.** `engine/classify_run.py`'s
`_classify_one_page` -- the single function BOTH `engine.index.RunIndex` and `classify_document`
call -- currently hardcodes `source_hash = "0" * 64` with the comment "neither caller ever decodes
an ID to bytes." D-10 makes THIS module the first caller that does. Left unfixed, every run_id ever
produced by `pdftool index` would carry the same all-zero stub, and a real per-op hash check against
the actual file's SHA-256 would refuse 100% of recipes -- the D-10 mechanism would be unreachable.
The fix is a root-cause one: thread a real `source_hash: str` parameter into the one shared function,
computed once by each of its two existing callers, rather than adding a workaround in this plan.

**Module shape (interface-first, three layers):**
1. `parse_recipe` -- D-09's JSON boundary: `bytes` in, `tuple[RecipeOp, ...]` out. Bounded per the
   Security Domain's DoS pattern (`MAX_RECIPE_OPS`, `MAX_NEW_TEXT_CHARS`), stdlib `json.loads` only.
2. `plan_recipe` -- the pure resolution/validation engine. Opens the target document read-only,
   resolves every op against `classify_document`'s output, D-10 hash-checks, runs the fit ladder
   (03-03) and the D-05/Pattern-4 substitution trigger (03-04) for every op, and returns a
   `RecipeReport` -- structured data, never printed here. This IS D-03's dry-run computation.
3. `apply_recipe` -- calls `plan_recipe` first; if any op failed, returns that report unchanged and
   writes nothing (D-11). If every op resolved cleanly, builds exactly one subset per
   (family, variant) actually used across the whole recipe (D-13), rewrites every op via
   `rewrite_run`, and saves only if every rewrite also succeeds -- `rewrite_run`'s own D-04 guard is
   a second, independent check after real mutation, so a plan-time pass is not a save-time guarantee
   until this final loop completes clean.

Purpose: makes "replace text across every page and have the output look like nothing happened" a
runnable CLI command for the first time, with the disclosure-before-commit and all-or-nothing
guarantees the roadmap requires actually enforced end to end.

Output: `engine/recipe.py`, `tools/pdftool.py`'s new `edit` subcommand, `tests/test_recipe.py`,
`tests/test_pdftool_edit.py`, the `source_hash` root-cause fix in `engine/classify_run.py` and
`engine/index.py`, and `engine/fit.py`'s `load_font` promotion.
</objective>
