## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `github.com/liberationfonts/liberation-fonts` release archive -> `fonts/` | Untrusted network fetch of binary font assets that get embedded into every future rewrite output; the only integrity control available is source-pinning (exact release tag/URL) plus structural/lineage verification, since upstream provides no signature |
| Debian trixie apt repository -> `Dockerfile.ci` build | A new CLI dependency (`opentype-sanitizer`) enters the CI build image, matching the existing qpdf/poppler-utils/mupdf-tools pattern already established in this file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-01 | Tampering | Liberation font tarball fetched from GitHub | mitigate | Pin to the exact release-file URL for tag `2.1.5` (never a mirror or an older Ascender-era redistribution, per D-07); verify `LiberationSans-Regular.ttf` inside the fetched tarball is byte-identical (`diff -q`) to the already-vetted `spike/fixtures/LiberationSans-Regular.ttf` before trusting the other 11 files share its lineage; `tests/test_font_fstype.py` additionally proves every one of the 12 files parses as a well-formed `TTFont` with the expected `OS/2` table -- a corrupted or truncated download fails loudly there, not silently later during subsetting (03-05) |
| T-03-02 | Tampering / Supply Chain | `opentype-sanitizer` apt package added to `Dockerfile.ci` | accept | BSD-3-Clause, verified directly against the upstream `LICENSE` file (03-RESEARCH.md Standard Stack section); pinned to an exact Debian trixie version string (`8.2.1+dfsg-2`, never `latest`), matching every sibling tool in this file; installed as a CLI subprocess only -- never enters the AGPL-gated resolved Python lockfile CLAUDE.md's licensing constraint governs, and is never `pip install`-ed as a project dependency in this plan |
| T-03-03 | Denial of Service | Malformed/hostile font-program parsing | accept (not applicable to this plan) | The fonts this plan touches are bundled, version-pinned, upstream-authored assets this project controls, not arbitrary documents from an untrusted user. 03-RESEARCH.md's "malformed embedded font program" DoS pattern applies to the *original document's* fonts (03-04/03-05's concern, a genuine untrusted-input boundary), not this plan's own trusted asset bundle |
