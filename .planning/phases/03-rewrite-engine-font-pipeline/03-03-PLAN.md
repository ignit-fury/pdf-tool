From engine/encoding_table.py (lines 551-583):
```python
def cid_width(descendant_font: pikepdf.Object, cid: int) -> float:
    """C-4: /W's nested run-length format -- `[c [w w w] cFirst cLast w ...]` -- with /DW
    default 1000. Never /Widths, never /MissingWidth: those are the SIMPLE-font width keys
    and do not apply to CIDFonts at all.

    IMPORTANT 4: /W's shape is attacker-controlled (an untrusted upload), so a truncated
    array -- `[3 [100] 10]` (a dangling cFirst with no cLast/width after it) or `[3]`
    (a bare code with nothing after it at all) -- must classify (fall through to /DW)
    rather than raise IndexError.
    """
```
Call as `cid_width(font["/DescendantFonts"][0], cid)`, where `cid` is the CID (for
`/Encoding /Identity-H`, the 2-byte code space IS the CID space -- no translation table).
Returns the width in thousandths of text space, same units `read_original_advance_pt`'s
existing `/Widths` path already divides by 1000 and multiplies by `font_size_pt`. `cid_width`
already implements "classify, never crash" for a malformed `/W` -- reuse gets that defense
for free.

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `engine.fit.read_original_advance_pt` <-> the original document's font dictionary (`/Widths`, `/FirstChar`/`/LastChar`, `/W`, `/DescendantFonts`) | Untrusted: any field of an uploaded PDF's font dictionary may be missing, truncated, or adversarially shaped |
| `engine.fit`'s shaping functions <-> `font_path` (uharfbuzz `hb.Face`/`hb.Font`) | Trusted in this plan's own scope: every call site in `engine/fit.py` and `tests/test_fit.py` points `font_path` at the bundled Liberation font or the fixture's own reference font, never bytes extracted from an original document |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-01 | Denial of Service | `read_original_advance_pt`'s `/Widths` and `/W` reads | mitigate | Bounds-check every code against `FirstChar..LastChar` AND the actual `/Widths` array length before indexing, raising a named `ValueError` instead of an uncaught `IndexError`; the Type0/CID path delegates entirely to `engine.encoding_table.cid_width`, which already classifies a truncated `/W` run-length entry to the `/DW` default rather than raising (reuse, not reimplementation, per D-14) |
| T-03-02 | Information Disclosure | `ValueError` messages raised on refusal | mitigate | Messages carry only the numeric character code and the `FirstChar`/`LastChar`/array-length bounds, never the decoded character or any surrounding original document text -- a deliberate deviation from the spike, which embedded `{ch!r}` directly; proven by `test_widths_refusal_messages_omit_decoded_character` |
| T-03-03 | Tampering | `hb.shape()` / `hb.Face.from_file_path` calls in `shape_advance_pt` | accept | Every call in this plan's own scope loads a trusted, bundled font file, never bytes read from an original document's embedded font program; shaping an *original* document's own embedded font is a later plan's concern (03-04's edit-time glyph-availability check), out of `engine/fit.py`'s boundary |
