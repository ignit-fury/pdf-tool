  <behavior>
    - cluster_page(glyph_records, glyph_verdicts) -> list[RunRecord]: bands glyphs by baseline
      (within +/-0.2 times em overlap, projected onto the text rendering matrix's line direction, not
      raw device y, so rotated text works); sorts each band by projected position BEFORE computing
      gaps (Pitfall 3, the two-column requirement); breaks a run on font-identity change, size change
      (over 1%), baseline/rise shift (a superscript is Ts-nonzero with no horizontal reset; a line
      break is a horizontal reset or a rise of over 0.5 times font size), a VISIBILITY TRANSITION
      (GlyphRecord.visible flipping invisible<->visible, i.e. crossing into or out of Tr 3 / Tr 7),
      fill-colour change (D-01's extension), a gap over BREAK_EM, a direction reversal (over
      0.2 times font size backwards), and a bad glyph per glyph_verdict (D-05 -- the run splits, the
      bad glyph becomes its own single-glyph locked record, per D-02).

      A within-visible gstate.render_mode value change does NOT break a run: Tr 0 (fill), Tr 1
      (stroke) and Tr 2 (fill+stroke) are all visible and must cluster together. D-01 deliberately
      rejected stroke mode and text render mode as break conditions; only fill colour was adopted.
      Break on the derived GlyphRecord.visible boolean, never on the raw render_mode value --
      phrasing this as "render-mode change" is what the acceptance criterion below is written to
      catch, since a stroke-mode-only fixture must NOT split.
    - Within a run, a gap strictly between K_EM times em and BREAK_EM times em inserts a synthetic
      space into the run's display text only -- no glyph record, no byte offset.
    - Each contiguous editable sub-run gets its own run ID via engine.run_id.encode_run_id's sub-run
      range segment (D-02).
  </behavior>
