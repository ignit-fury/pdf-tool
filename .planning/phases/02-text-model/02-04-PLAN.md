<contents_coalescing_ruling>
## RULING 2026-08-13 — supersedes Pattern 2's per-part parsing

Executing Task 1 proved that parsing `/Contents` parts in ISOLATION desyncs the two-pass alignment
assertion on **46 of 217 corpus documents (21%)**. Root cause, verified at byte level on
`corpus/public/govdocs1_000_000010.pdf`: a text-showing operator's operand array legitimately closes
in one part while its keyword opens the next (part 0 ends `...(cket No. 05-185 )]`, part 1 begins
`TJ\n`). This is legal per ISO 32000-1 §7.8.2. `govdocs1_002_002167.pdf` — the file this plan names
for the QBT fusion test — is one of the 46.

**Both naive approaches are wrong.** Naive byte-concatenation fuses `Q`+`BT` into `QBT` (qpdf #444,
what TEXT-07 forbids). Per-part isolation splits operators from their operands.

**The ruling: COALESCE the parts with a newline separator into ONE parse stream, while recording
each part's byte range so run IDs still encode part + byte-offset-within-that-part.** The separator
prevents fusion; the single parse sees operators whole; addressing by part is preserved, which
Phase 3's rewrite engine needs in order to write edits back into the correct stream object.

Pattern 2's title — "parts are addressed, never concatenated" — conflated *addressing by part* with
*parsing in isolation*. The research said "coalesced before parsing". Addressing and parsing are
separate concerns. TEXT-07 is satisfied by the separator, not by isolation.

This removes the 46-document allowlist entirely rather than maintaining it.
</contents_coalescing_ruling>
