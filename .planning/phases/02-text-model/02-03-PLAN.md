  <behavior>
    - GlyphRecord is a frozen dataclass, slots=True, with exactly these 13 fields: code: CharCode,
      glyph: GlyphId | None, unicode: Unicode | None, x: float, y: float,
      advance: tuple[float, float], font_id: int, render_mode: int, visible: bool, stream_id: int,
      operator_byte_offset: int, item_index_within_tj: int | None, byte_offset_within_string: int.
    - RunRecord is a dataclass carrying: run_id: str, glyphs: list[GlyphRecord], display_text: str
      (with synthetic spaces inserted by the clusterer), page: int.
    - encode_run_id(source_hash, page, part, xobj_path=(), annot=None, pattern=None, charproc=None,
      byte_offset, subrange=None) -> str produces exactly:
      {sourceHash}:p{page}:c{part}[/x{xobjObjid}]*[/a{annotIdx}:{apState}][/t{patternObjid}]
      [/y{charProcName}]:o{byteOffset}[:g{start}-{end}]
      where source_hash is a SHA-256 hex digest (per the Security Domain V6 note, matching
      corpus/manifest.json's existing sha256 convention).
    - decode_run_id(run_id: str) -> RunIdParts round-trips: encode_run_id(**decode_run_id(x)) == x
      for at least one ID of each optional-segment shape (bare page/part; with one xobj hop; with an
      annotation; with a sub-run range). decode_run_id raises a typed ValueError on a malformed
      string -- it uses a strict regex match, never eval or unchecked string splitting, since Phase 4
      will eventually echo run IDs back from an untrusted client.
    - resolve_run_id_offset(run_id: str, original_bytes_by_part: dict[int, bytes]) -> bool seeks to
      the decoded byte offset within the decoded part's original bytes and confirms an operator
      keyword token starts there.
  </behavior>
